# v0.2 — Frozen implementation contract (read before coding)

Companion to [V0.2-ConnectedTwin.md](V0.2-ConnectedTwin.md). The C# types are in `server/src/TwinLabs.Core` (`Contracts/Plant.cs`, `Runtime.cs`, `Messages.cs`, `Abstractions.cs`). The TypeScript mirror is `ui/src/net/contracts.ts`, and examples are in `contracts/examples`. These are **frozen**: if you need a change, work around it and report it.

**Interfaces** (`Abstractions.cs`): `ITagSource` / `ITagSourceFactory` / `TagUpdate` (clients of OPC UA and MQTT), `ITwinPublisher` (the virtual PLC and the MQTT publisher, called once per sim second), and `IHostEventSink` / `IHistoryStore` / `IScenarioStore` / `ILayoutStore` / `IMeshStore` (persistence).

**Shared code:** `TwinLabs.Connect.BindingResolver` validates bindings and turns `TagUpdate`s into `ResolvedUpdate`s (scale, offset and stateMap applied). Every adapter and shadow mode use it. Do not re-implement it.

## Node-id naming (virtual PLC and bindings)
`ns=2;s=<LineId>.<AssetId>.<Name>`
- `LineId` is the plant id in PascalCase, split on `-` and `_` (`line-a` → `LineA`). A trailing `-connected` is dropped, so the plant `line-a-connected` also publishes under `LineA`.
- `Name` for assets: `State, Good, Scrap, Wip, Load, Wear`. For sensors: `temp→Temp, vib→Vib, power→Power, current→Current, speed→Speed, level→Level, rejects→Rejects, good→Good`.
- `State` is an Int32 in enum order (off=0 … maintenance=6). Everything else is a Double.
- Several bindings may share one address (the sink's `Good` is both a sensor and an asset counter).

## MQTT publisher (`MqttSimPublisher`, config `Twin:Mqtt`)
- Topic: `<lineId>/<assetId>/<name-lowercase>` (same names and `LineId` rule as above), payload `{"value":<number>,"t":<simMs>}` (state as an integer).
- An embedded broker (MQTTnet server) runs when `Twin:Mqtt:Broker:Enabled` is true (`Port` default 1883).
- `contracts/plant/sample_line.mqtt.json` uses `jsonPath` `$.value` and is owned by the mqtt agent.

## Config keys
| Key | Meaning |
|---|---|
| `Twin:Mode` | `simulate` (default) or `shadow` |
| `Twin:VirtualPlc:Enabled` / `Port` | the virtual OPC UA server (default off, port 4840) |
| `Twin:Mqtt:Broker:Enabled` / `Port`, `Twin:Mqtt:Publish:Enabled` | the MQTT publisher and its embedded broker |
| `Twin:Data:Path` | the SQLite file and mesh folder (default `./data`) |

## Shadow mode semantics
- External updates are applied to the live state (asset state and counters, sensors). The engine keeps running as a **predictor** from the real state; its own sensors and counters are used only for comparison.
- A tag value older than 5 s (wall clock) is stale and falls back to the prediction.
- `deviation` alarms: |actual − predicted| > max(3σ of the prediction baseline, 10% of |predicted|) for 10 consecutive samples, only for sensors that have a binding. They clear after 10 calm samples. Id: `ALM-{sensorId}-deviation`.
- The mode switches at runtime (`POST /api/twin/mode`). Switching to shadow requires at least one binding (409 otherwise) and resets the predictor. `SimStatus.mode` always reports the current mode.
